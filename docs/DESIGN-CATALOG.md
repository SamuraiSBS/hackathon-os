# Optional design catalog

The Hackathon OS template does not bundle a design catalog, framework-specific component library, or fixed visual identity. A team may use a separate catalog or design system when it is available and relevant to the brief.

## When to consult it

First read the challenge brief and choose the application stack. Then look for components and patterns that support the primary user journey and fit the contest constraints. Do not let a catalog's framework, dependencies, or visual style decide the project's stack or product scope.

## Transfer a component or pattern

1. Identify the exact element, its intended user task, and required states.
2. Check whether its implementation fits the selected stack. If it does not, transfer the behavior and visual rules as a reference and adapt them to the project.
3. Review the original source, revision, license, dependencies, responsiveness, keyboard use, focus behavior, contrast, reduced motion, and touch alternatives.
4. Copy source code only when the applicable license and project constraints permit it. A catalog listing or demo URL is not, by itself, permission to redistribute the source.
5. Integrate only the elements needed by the P0/P1 scope, then verify them in the actual user flow.

If no compatible catalog is available, continue with the chosen stack and the project's own design decisions; catalog access is never a blocker for the hackathon.
