# Цикл комплексного улучшения проекта

Этот необязательный режим помогает находить и выполнять улучшения в уже существующей кодовой базе. Запускай его после появления сквозного P0-сценария, между этапами разработки или по явной просьбе пользователя. Он не заменяет цикл хакатона и не должен запускаться перед каждой обычной задачей.

## Запуск

- **«Улучшай проект»** — обычный аудит: первый запуск создаёт карту всего проекта; последующие сверяют прежние находки и изучают изменения вместе с затронутыми зависимостями и сценариями.
- **«Улучшай проект глубоко»** или **«полный аудит»** — повторно проходит все применимые области проекта.

Подробная процедура находится в `.agents/skills/improve-project/SKILL.md`. Агентские роли для Codex Desktop/CLI заданы в `.codex/agents/`, для OpenCode — в `.opencode/agents/`.

## Цикл работы

1. **Оркестратор аудита** изучает инструкции проекта, состояние Git, актуальные документы, существующую карту и незакрытые находки. Первый запуск или глубокий аудит охватывает весь проект. Секреты, кеши, сборки и необработанные медиа не читаются как исходный код; непроверенные области указываются явно.
2. **Специалисты** независимо проверяют продукт, идеи, дизайн и доступность, инженерное качество, надёжность и безопасность. На первом запуске или при устаревшей карте добавляется картограф проекта. Каждый специалист возвращает отдельный отчёт с доказательствами и границами проверки; оркестратор сохраняет отчёты. Профили аудита запрещают правки там, где рантайм умеет это ограничить. Если исходники всё же изменились во время аудита, не восстанавливай их автоматически: сохрани изменения и останови затронутую реализацию до решения пользователя.
3. **Оркестратор** сверяет цитируемые пути и поведение, объединяет дубли, отделяет наблюдения от выводов и гипотез, ранжирует находки и сохраняет отчёты, статусы и handoff в `.improve/`.
4. **Новая сессия реализации** читает handoff, заново проверяет Git и свежесть каждой задачи и запускает подходящих `developer-*` агентов. Реализация не выполняется в чате аудита.
5. **Оркестратор реализации** проверяет diff и записывает результат и фактические проверки в тот же каталог запуска.

## Граница самостоятельной реализации

Автоматически выполнять можно только подтверждённые фактами, высокоуверенные, ограниченные и обратимые улучшения, которые сохраняют задокументированное пользовательское поведение. Для каждого пункта нужны чёткий результат и критерии приёмки.

Выбор пользователя нужен для удаления или добавления пользовательской функции, заметного изменения рабочего процесса или правил продукта, миграции или удаления пользовательских данных, изменения публичного/API-контракта, подключения платного или внешнего сервиса и любого нерешённого продуктового решения. Идеи субагента — кандидаты на оценку, а не разрешение менять продукт.

Система не коммитит, не отправляет изменения в remote, не публикует и не развёртывает их автоматически. Не запускай тесты, если пользователь или правила проекта этого не требуют.

## Результаты и среды

Git игнорирует локальную папку `.improve/`. В ней хранятся компактная карта, отчёты аудита, единый реестр находок, handoff и журнал реализации. Сохраняй предыдущие запуски, чтобы не терять историю и не повторять закрытые рекомендации без повторной проверки.

Общие инструкции и отчёты одинаковы для всех сред; отличается только способ запустить свежую сессию:

- **Codex Desktop:** используй текущий проект и тот же checkout. Если подключённый инструмент Codex умеет создать новый чат/задачу, передай путь к handoff. Если нет, оставь точный текст для нового чата и не продолжай реализацию в чате аудита.
- **Codex CLI:** из корня проекта запусти новый `codex exec` с указанием handoff, не возобновляя чат аудита.
- **OpenCode:** для аудита доступна команда `/improve-project`; реализация запускается отдельной командой `opencode run --agent project-improver --file <путь-к-handoff> "Implement only the auto-eligible tasks in this handoff"` из корня проекта.

Если среда не может создать отдельную сессию, сохрани полный handoff, укажи точную команду или текст для ручного запуска и отметь запуск как ожидающий реализации.

Актуальные форматы сред сверяй с официальной документацией: [Codex subagents](https://developers.openai.com/codex/subagents), [Codex CLI](https://developers.openai.com/codex/cli), [OpenCode skills](https://opencode.ai/docs/skills), [agents](https://opencode.ai/docs/agents), [commands](https://opencode.ai/docs/commands) и [CLI](https://opencode.ai/docs/cli/commands).
